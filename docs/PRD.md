# 생각하는 공방 제품 요구사항 (PRD)

기준일: 2026-11-25 (KST) · 처음 작성 2026-11-17
원본 문서: 사용자 스토리 문서(Claude Docs)와 같은 내용을 에이전트가 읽기 쉽게 옮긴 것입니다. 둘이 다르면 이 파일을 먼저 고치고 사람에게 알립니다.
AI 도우미와 포트폴리오 안내 챗봇의 문제 정의, 가설, 지표는 블로그 과제 기획서 [PRD-thinkandmake.md](PRD-thinkandmake.md) 에 있습니다.

## 1. 한 줄 요약

AIPM 수업을 복습하는 블로그 "생각하는 공방"(THINK & MAKE). **관리자만 글을 쓰고, 회원은 읽고 댓글을 단다.** 글마다 AI 가 미리 만든 3줄 요약을 보여 주고, 오른쪽 아래 챗봇이 블로그와 포트폴리오 질문에 답한다.

- 주소: https://mopnt135.github.io/thinkandmake/
- 지금은 Supabase 를 연결하지 않은 **체험 모드**다. 글, 댓글, 회원은 방문자 브라우저에만 저장되고, 모두에게 보여야 하는 글은 `index.html` 안의 파일 글로 둔다(US-11).

## 2. 사용자와 권한

| 할 수 있는 일 | 방문자 | 회원 | 경고 받은 회원 | 추방된 회원 | 관리자 |
| --- | --- | --- | --- | --- | --- |
| 공개글 읽기 | O | O | O | O | O |
| 나만보기(초안) 글 읽기 | X | X | X | X | O |
| 댓글과 답글 쓰기 | X | O | O | X | O |
| 내 댓글 고치기 | X | O | O | X | O |
| 내 댓글 지우기 | X | O | O | O | O |
| 남의 댓글 지우기 | X | X | X | X | O |
| 글 쓰기, 고치기, 지우기 | X | X | X | X | O |
| 파일 첨부 | X | X | X | X | O |
| 회원 경고, 추방, 되돌림 | X | X | X | X | O |

- 가입하면 바로 **회원**이 된다. 승인 절차는 없다.
- 관리자는 **1명**. Supabase 연결 뒤에는 관리자 지정을 Supabase SQL Editor 에서만 한다.
- 체험 모드에서는 관리자 로그인 화면에서 **비밀번호만** 넣어 관리자가 된다(11-25). 이메일 로그인은 모두 회원이다.
- 댓글 작성자 이름은 **이메일 앞 3글자 + \*\*\*** 로 보인다. 예: kim\*\*\*

## 3. 사용자 스토리

형식: 관리자로서 나는 ○○하고 싶다. 그래야 ○○할 수 있다.
상태: 됨 / 일부 됨 / 안 됨

### US-1 관리자가 로그인한다 · 됨
- [x] 체험 모드: 관리자 로그인 화면에 비밀번호 칸 하나. 코드에는 비밀번호 글자 대신 SHA-256 값만 둔다. 틀리면 "비밀번호가 맞지 않습니다" 로 안내한다. (11-25)
- [x] 메뉴의 "관리자"와 맨 아래 링크에서 관리자 로그인 화면으로 간다. (첫 화면 바로가기 칸은 11-24 레이아웃 변경으로 없앴다)
- [x] 관리자면 회원 관리 화면으로 바로 이동한다.
- [x] 관리자가 아니면 "관리자 계정이 아닙니다" 안내가 나온다.
- [x] 비밀번호가 틀리면 어느 쪽이 틀렸는지 알려주지 않는다.
- [x] 관리자인지는 서버 규칙으로 확인한다.

### US-2 관리자가 글과 공지를 작성한다 · 일부 됨
- [x] 글쓰기 메뉴와 버튼은 관리자에게만 보인다.
- [x] 회원이 글쓰기 주소로 오면 "생각하는 공방의 글은 관리자만 씁니다" 안내가 나온다.
- [x] 글은 공개 또는 나만보기(관리자 초안)로 올린다.
- [x] 관리자는 모든 글을 고치고 지운다. 삭제는 두 번 눌러야 한다.
- [x] 회원이 글을 저장하려 하면 서버가 거절한다.
- [ ] 글쓰기 화면에서 "공지로 올리기"를 고를 수 있다. **지금은 공지가 `index.html` 에 고정되어 있다.**
- [x] 글쓰기 분류에 기획, 이미지, 오늘의 프롬프트가 있다. (11-25)
- [x] 글에 JPG, PNG, GIF, PDF 파일을 5개까지 첨부한다. 파일당 10MB.

### US-3 관리자가 불필요한 댓글을 삭제한다 · 일부 됨
- [x] 모든 댓글 옆에 "관리자 삭제" 버튼, 두 번 눌러야 지워진다.
- [x] 회원은 내 댓글만 고치고 지운다.
- [x] 작성자 이름은 서버가 정하고 가려서 보여준다.
- [x] 관리자 화면 "댓글 현황"에서 모든 댓글을 글 제목, 작성자, 시각과 함께 본다. 전체, 오늘, 숨겨진 댓글로 거른다.
- [x] 회원별 댓글 수가 회원 관리에 보인다.
- [ ] 삭제할 때 운영 기준 번호를 사유로 고른다.
- [ ] 누가 언제 왜 지웠는지 관리 기록에 남는다.

### US-4 관리자가 질 나쁜 유저에게 경고를 준다 · 일부 됨
- [x] 회원 줄에 경고 버튼과 경고 횟수(예: 2/3)가 보인다.
- [x] 경고 3회면 서버가 자동으로 추방한다. 세 번째 경고는 두 번 눌러야 한다.
- [ ] 경고 사유를 적는다.
- [ ] 경고 받은 회원은 다음 로그인 때 사유와 남은 횟수를 본다. 이메일은 보내지 않는다.
- [ ] 잘못 준 경고를 취소한다.

### US-5 관리자가 질 나쁜 유저를 추방한다 · 일부 됨
- [x] 추방은 두 번 눌러야 한다.
- [x] 추방된 회원은 글은 읽지만 댓글을 쓰거나 고칠 수 없다.
- [x] 추방된 회원의 댓글은 다른 방문자에게 숨겨지고 관리자에게는 보인다.
- [x] 관리자는 추방될 수 없다.
- [x] 추방을 되돌리면 경고 0회 회원이 되고 댓글이 다시 보인다.
- [ ] 추방 사유를 적고, 추방된 회원이 로그인하면 사유를 본다.
- [ ] 추방된 이메일로 다시 가입할 수 없다.

### US-6 관리자가 로그아웃한다 · 됨
- [x] 모든 화면 위쪽에 로그아웃 버튼이 있다.
- [x] 로그아웃하면 첫 화면으로 가고 관리 버튼이 사라진다.
- [ ] 뒤로 가기를 눌러도 관리 화면 내용이 다시 보이지 않는지 실제 Supabase 로 확인한다.

### US-7 회원이 댓글에 답글을 단다 · 됨
회원으로서 나는 다른 사람의 댓글에 바로 답하고 싶다. 그래야 대화가 어느 댓글에 대한 것인지 알 수 있다.
- [x] 로그인한 회원과 관리자에게 댓글마다 "답글" 버튼이 보인다. 방문자와 추방된 회원에게는 없다.
- [x] 답글은 부모 댓글 아래에 들여 쓰고 "답글" 표시를 붙인다.
- [x] 답글은 한 단계만. 답글에는 답글 버튼이 없고, 서버도 답글의 답글을 부모 댓글로 모은다.
- [x] 다른 글의 댓글에는 답글을 달 수 없다 (서버가 거절).
- [x] 답글이 달린 댓글을 지우면 "삭제된 댓글입니다"만 남고 답글은 유지된다.
- [x] 관리자가 남의 댓글을 고치려 하면 서버가 삭제 표시로만 바꾼다. 본문은 고칠 수 없다.
- [x] 삭제 표시된 댓글은 다시 고칠 수 없다.

### US-8 관리자가 방문 통계를 본다 · 됨
관리자로서 나는 누가 얼마나 오고 어떤 글을 읽는지 알고 싶다. 그래야 다음에 쓸 글을 정할 수 있다.
- [x] 홈과 페이지별 방문자 수를 GA4 에서 본다.
- [x] 지역, 기기, OS 통계를 GA4 에서 본다.
- [x] 글별 조회수와 끝까지 읽은 수를 본다.
- [x] 이메일, 댓글 본문은 GA 로 보내지 않는다.
- [x] 방문자는 "방문 통계 끄기"로 거부할 수 있다.
- [x] GA4 측정 ID `G-5HJBBKMVE3` 를 넣고 배포했다 (2026-11-17)
- [ ] GA4 관리 화면 설정: 향상된 측정의 페이지 변경 끄기, 맞춤 정의, 내부 트래픽 필터 (docs/ANALYTICS.md 4장)

### US-9 방문자가 검색이나 공유 링크로 글을 찾는다 · 일부 됨
방문자로서 나는 검색 결과나 카카오톡 링크에서 어떤 글인지 미리 알고 싶다. 그래야 들어갈지 정할 수 있다.
- [x] 공개글과 공지마다 고유 주소(`/p/글번호/`)가 있고, 글마다 제목, 설명, 썸네일이 다르다.
- [x] 관리자는 글쓰기 화면에서 "검색 설명"(160자, 선택)을 적는다. 비우면 본문 앞부분을 쓴다.
- [x] 나만보기 글은 페이지를 만들지 않고 공유 버튼도 없다.
- [x] 글 상세에 "공유 링크 복사" 버튼이 있다.
- [x] 썸네일에 글 제목과 본문 앞줄이 들어가고, 첨부 사진이 있으면 첫 사진도 들어간다. 파일 글은 자기 그림을 넣는다.
- [x] 사진이 있는 썸네일에서도 맨 아래 줄이 겹치지 않는다. (11-25)
- [x] 사이트맵과 robots.txt 로 검색엔진에 페이지 목록을 알린다.
- [ ] 새 글이 반영되기까지 최대 반나절 걸린다(하루 2번 자동 생성).
- [ ] Google Search Console, 네이버 서치어드바이저에 사이트 등록 (사람이 할 일).

### US-10 방문자가 글 메뉴로 글을 고른다 · 됨 (11-25)
방문자로서 나는 기획서, 그림, 프롬프트처럼 종류별로 글을 보고 싶다. 그래야 관심 있는 것만 빨리 찾는다.
- [x] 헤더 "글 목록" 아래 소메뉴에 기획, 이미지, 오늘의 프롬프트가 있다. 컴퓨터는 마우스를 올리거나 Tab 으로 펼치고, 휴대폰은 메뉴 안에 늘 보인다.
- [x] 첫 화면 메인 사진 아래에 같은 세 메뉴가 글씨 카드(이름과 글 수)로 있다.
- [x] 메뉴를 누르면 그 분류의 글만 모여 보인다. 글이 없으면 "아직 글이 없습니다" 로 안내한다.
- [x] 글 목록의 분류 버튼에 파일 글의 분류(자기소개 등)도 나온다.

### US-11 모든 방문자가 파일 글을 본다 · 됨 (11-25)
관리자로서 나는 Supabase 연결 전에도 소개 글과 작품을 모두에게 보여 주고 싶다. 그래야 포트폴리오로 쓸 수 있다.
- [x] 소개 글(PM 이 되고 싶은 이유, 이름의 뜻, 헬멧 고양이 그림), 기획 PDF 글 2편, 오늘의 프롬프트 글 1편, 이미지 글 3편을 `index.html` 에 둔다.
- [x] 기획 글은 "PDF 내려받기" 버튼이 있다. 용사 키우기 PDF 는 작성자 실명을 지운 파일이다.
- [x] 오늘의 프롬프트 글은 프롬프트를 줄바꿈 그대로 상자에 보여 주고 "프롬프트 복사" 버튼이 있다.
- [x] 파일 글에는 수정, 삭제 버튼이 없다. 내용은 사람의 확인을 받고 고친다.
- [x] 검색·공유 페이지(`p/about/`, `p/plan-1/` 등)도 생성기가 만든다.

### US-12 방문자가 챗봇에게 블로그를 묻는다 · 됨 (11-24 ~ 11-25)
방문자로서 나는 글을 다 읽지 않고도 블로그와 주인에 대해 바로 묻고 싶다. 그래야 둘러볼지 정한다.
- [x] 오른쪽 아래 블로그 로고와 "질문해주세요" 버튼. 대화창 제목은 "생각하는 공방", 챗봇 말풍선 옆에 로고 얼굴이 있다.
- [x] 대표 질문 버튼 8개, 직접 적은 질문도 미리 만든 답(30여 개)에서 찾아 답한다. 블로그와 무관한 질문은 범위를 안내한다.
- [x] 글 내용으로 만든 답에는 "이 글 읽기" 링크, 예시 작품 답에는 그림이 붙는다(예시 작품은 실제 포트폴리오가 아니라고 밝힌다).
- [x] 방문자가 물을 때 AI 를 부르지 않는다. 답은 자동 실행이 `portfolio/profile.md` 와 공개글로 미리 만든다.

### US-13 관리자가 예시 데이터로 관리 화면을 확인한다 · 됨 (11-25)
- [x] 체험 모드는 처음 열 때 예시 회원 6명(example.com, 경고 1명, 추방 1명)과 예시 댓글 12개를 넣는다.
- [x] 예시 댓글은 실제 글에 달려 댓글 현황과 이어진다. 댓글, 댓글 현황, 회원 목록에 "예시" 표시가 붙는다.

## 4. 결정 사항

| 질문 | 결정 |
| --- | --- |
| 누가 글을 쓰나 | 관리자만 |
| 누가 댓글을 다나 | 로그인한 회원. 가입하면 바로 |
| 몇 번 경고면 추방 | 3회, 자동 |
| 추방된 회원의 댓글 | 모두 숨김. 되돌리면 다시 보임 |
| 경고와 추방 알림 | 블로그 화면에서만. 이메일 없음 |
| 관리자 수 | 1명 |
| 첨부 파일 | JPG, PNG, GIF, PDF. 파일당 10MB, 글당 5개 |
| 나만보기 | 관리자 초안 용도로만 |
| 답글 깊이 | 한 단계. 답글의 답글은 부모 댓글로 모음 |
| 검색·공유 썸네일 | 글마다 자동으로 그린 카드. 제목과 본문 앞줄을 넣고, 첨부 사진이 있으면 첫 사진도 넣는다. 공개글의 사진만 쓴다 |
| 운영 기준 | "생각하는 공방 운영 기준" 공지 (`NOTICE_RULES`) |
| 글 메뉴 | 기획, 이미지, 오늘의 프롬프트. 헤더 '글 목록' 소메뉴와 첫 화면 글씨 카드 (11-25) |
| 체험 모드 관리자 | 비밀번호만 입력. Supabase 연결 뒤에는 서버가 확인하는 이메일과 비밀번호 (11-25) |
| 모두에게 보일 글(체험 모드) | `index.html` 안의 파일 글. 사람 확인을 받고 고친다 (11-25) |
| 챗봇 답 | 미리 만든 답만. 방문자가 물을 때 AI 를 부르지 않는다 (11-24) |
| 예시 데이터 | 체험 모드에서만, "예시" 표시를 붙인다 (11-25) |
| **지운 글과 댓글 복구** | **다시 정해야 함.** 지금은 바로 지워짐 |

## 5. 운영 기준 요약

- 불필요한 댓글 5가지: 광고와 홍보, 같은 내용 반복, 출처 없이 옮김, 남의 개인정보, 의미 없는 글자
- 질 나쁜 이용자 5가지: 욕설과 비하, 차별, 불필요한 댓글 반복, 경고 뒤 되풀이, 다른 사람 사칭과 여러 계정
- 조치 순서: 댓글 삭제 → 경고 → 3회면 자동 추방

## 6. 범위 밖

- 댓글 첨부 파일
- 이메일 알림
- 여러 명의 관리자
- 글 서식(굵게, 표 등). 지금 본문은 글자만 받는다.
- 방문자가 물을 때 AI 가 실시간으로 답하는 챗봇 (키를 숨길 서버가 필요하고 수업 키가 11-25 에 끝난다)
- 영상 재생 (챗봇의 예시 영상은 한 장면 그림만 보인다)
